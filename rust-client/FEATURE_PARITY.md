# Electron → native feature parity

The target is feature parity with the working **Linux Electron port**, preserving its Zalo theme. Automatic saved-session restore/unsigned QR and exact original boundary-text canonicalization now pass local integration checks; the user's recurring storage mismatch still needs production retry. Rust is currently a partial implementation. An endpoint or menu in a bundle proves a code path exists, not that it works on Linux or is enabled for every account. Rows remain unaccepted until equivalent native behavior is tested. No private profile or production account was inspected for this inventory.

Evidence notation: **N** is the [shared renderer/worker bundle](../pc-dist/lazy/default-login-main-startup-shared-worker-znotification.9e3e92e88644da772301.js); **M** is [main.js](../main-dist/main.js). Numbers identify lines in this checkout. Native implementation evidence lives in [src](src/); current checks are in [MIGRATION_STATUS.md](MIGRATION_STATUS.md).

## Implementation order

1. Resolve current WSS interoperability and offline/empty/worker-stopped UI recovery. Keep local history and drafts usable; expose sanitized stage/category diagnostics.
2. Complete and validate contacts, group/conversation discovery, names/avatars/previews and recent-history synchronization with indexed account-scoped cache. The first directory/preview milestone is implemented; a freshly signed-in app still needs real-account acceptance and full history/avatars.
3. Complete ordinary text/history/status lifecycle, then Signal/E2EE with independent vectors and device-transition tests. Media and message actions must preserve the appropriate encryption capability.
4. Add remaining content/discovery/settings flows and Linux integrations, then backup/import and native packaging/update acceptance.

Directory evidence and bounds are recorded in [PROTOCOL_DIRECTORY.md](PROTOCOL_DIRECTORY.md). Independent E2EE Python/JS oracles are research evidence ([E2EE_CONTRACT.md](E2EE_CONTRACT.md)); they do not enable native encrypted messaging.

For each row: derive the actual bundle contract → add independent fixtures and failure tests → implement worker/storage/UI → validate offline and local TLS → run an authorized equivalent-account manual check. Record X11/Wayland/IME results and repeat representative workloads before any performance or replacement claim. This inventory is a starting checklist; newly discovered Electron controls must be added rather than silently omitted from “full parity.”
