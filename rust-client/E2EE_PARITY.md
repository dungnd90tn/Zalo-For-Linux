# E2EE parity: Electron behavior → Rust

Goal: every behavior of the original client's end-to-end encryption exists in the native client, ported from the
original's code, not re-derived. Source of truth: `PC` = `pc-dist/lazy/default-login-main-startup-shared-worker-znotification.9e3e92e88644da772301.js`,
`LS` = `pc-dist/libs/libsignal-protocol.static.js`. Line numbers are exact for those files.
Status: **done** (ported and tested), **partial** (some of it), **missing**, **n/a** (dead code or disabled in the original).
Tests named here are in `rust-client/`. This file is built from four read-only catalogs of the bundle; cluster B is in,
A, C and D are appended as they arrive.

## Framing facts used by everything (PC 37965, 403823-403837, 473155)

- Frame: `[version u8=1][cmd u16 LE][subCmd u8][JSON]`. `subCmd` defaults to **1** when omitted. Explicit `subCmd:0`:
  540, 541, 542, 543, 544, 547, 560, 563, 564, 580. **Sent with subCmd 1 (no explicit value): 545 acks, 557/558 acks.**
- Request id `signal_req_<n>` (counter from 0); request timeout **10 s** (`ERR_CONNECTION_TIMED_OUT`, `ERR_SOCKET_CLOSED`).
- Retry helper `De.b(fn, label, max, 15)`: one try then up to `max` retries at Fibonacci delays 1,2,3,5,8,13,15,15… s;
  aborts on `ERR_SOCKET_CLOSED` and on `error.code` in `[112,-69]`; ends with `"ERR_MAX_RETRY"`.
- Cipher string `base64(typeByte||body)`; type 3 = prekey message, anything else = ordinary. Device ids MOBILE 0, WEB 1, PC 2.
- Address name `${uid}_${deviceId}`. Per-address serialization (`SESSION_LOCK`) and per-uid serialization (`INIT_SESSION`).
- Config defaults (PC 226700-226900): `max_retry_submit/get_list/get_id/int_subdevice` 10, `time_to_reinitialize` 600000 ms,
  `enable_notify_delete_session` true, `build_init_msg_v2` true, `respone_fail_init_new_device` true,
  `pre_check_init_msg_type` true, `reinit_mismatch_iid` true, `timeout_ack_failed` 30000, `socket.offline_timeout` 480000,
  `abnormal_decrypt_init_fail_recover_new_bundle` true (period 7 days), `e2ee.enable` false locally (server config enables).

### Easy-to-miss facts from cluster B (each one is a bug if ported from memory)

1. 545 acks use frame subCmd 1; the 545 ack for a 548 event carries `cmd: 547`.
2. Offline session events (516/517) are applied only after **all** E2EE queues have arrived; messages carrying prekeys build their own sessions.
3. A failed 544 needs `iid` (local reg id) and the `ts` of the init being rejected; a success 544's data is an *encrypted* `{"subDevice":[…]}`.
4. `processInitAndAck` swallows unknown errors and still sends the success ack; duplicate counters on an init count as success.
5. `processOnly`: an init superseded by a later disable is decrypted (session exists) but not acked.
6. `buildSessionAllDevices` marks **all** known devices stale before rebuilding; a failure partway leaves them stale.
7. Own-uid ignore list `[-2,-3,-5,-7,-9.x]` vs other uids `-7` only (which sets `inactive`, excluding the device from the checksum and broadcast).
8. getlist pagination falls back to one unpaginated call on any pagination error.
9. Group paths (561/559/546/582) are dead by default (`group.deactivated: true`); `getCompatibleDevice` (560) has no callers.
10. `sendInitSession` `type` is 1/0 from `forwardSubdevice` in the main path but from `initType=="enable"` in the auto-upgrade service path.

## Send confirmation milestone (2026-11-11)

The existing parser already read `minGlobalMsgId`; older chronological notes describing that as missing are historical. The new request-bound reader validates an echoed `clientId` when present (numeric/string IDs normalize identically), preserves older HTTP-bound responses without it, and refuses conflicting `msgId`/`minGlobalMsgId`. The compatibility parser remains unchanged. The exact original-JS oracle has ten synthetic cases: the original helper lets an explicit `msgId` override `minGlobalMsgId`; refusing a contradictory pair is an intentional stricter native boundary, not a claim of identical source behavior.

A valid service ACK followed by acknowledgement/echo storage failure is now classified as **accepted, local confirmation not saved**, rather than unknown delivery. The fixed error contains no identifiers or transport payload. It cannot restore ciphertext to a sendable state. The UI review settles only its matching pending request and preserves newer draft edits. Targeted checks pass 50 E2EE tests, two independent ACK integration tests and the ten-case source oracle; full-suite results belong in `VALIDATION.md`. These are offline/synthetic proofs, not a successful real-account send.

Next D11 work is startup repair of current-account acknowledged chat rows (excluding `init-*`), restoring local echoes idempotently without HTTP or encryption and publishing only in the current privacy/account scope. D2 still needs authoritative per-device coverage, stale/registration-ID transitions and offline-queue ordering; the existing any-session shortcut is not full recipient readiness. Neither remaining item is implemented by this milestone.
